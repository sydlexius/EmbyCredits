Credits Detection

Hash Detection: Uses audio fingerprinting (Chromaprint) to compare episodes in a season. Works out of the box with no extra setup.
OCR Detection: Reads on-screen text to find the credits. Very precise, but requires an OCR engine (Docker container or local Tesseract, see Setup Guide tab).
With Fallback: If the primary method fails to detect credits, the fallback method is tried automatically.
Black Frame Detection Only: Uses only black frame analysis. Works per episode without requiring the full season.

TheIntroDB Community Database

When enabled, the plugin will first query TheIntroDB community database for credits timestamps before running local detection. If a timestamp is found in the database it is used directly, skipping CPU-intensive detection entirely. Local detection only runs as a fallback when no database entry exists.

Default: Off. Query the community database for credits timestamps before running detection. No account or API key required.

Hardware Acceleration

Default: Off. Use the GPU to decode video instead of the CPU. One setting for the whole plugin: it is used for OCR frame extraction, black frame detection and the post-credits scene check. Detection results are not affected. Requires a compatible GPU and drivers, so test it on a few episodes first.
VAAPI: Intel UHD/AMD on Linux (use /dev/dri/renderD128)
QSV: Intel Quick Sync (Windows/Linux)
CUDA/NVDEC: NVIDIA GPUs (CUDA for older, NVDEC for newer)
D3D11VA: Windows modern hardware acceleration
VideoToolbox: macOS Apple Silicon or Intel Macs
Usually left empty. For VAAPI on Linux use /dev/dri/renderD128 (or renderD129 for a second GPU). For QSV, enter the device index if needed. For CUDA, enter the GPU index (0, 1, etc.).

HDR Video

Default: Off. Convert HDR10, HLG and Dolby Vision (with an HDR10 base) frames to normal brightness before they are read by OCR. It helps OCR read credits shown over the picture; white text on black reads fine without it. It is only used when OCR detection runs (OCR detection mode, an OCR fallback, anime OCR or an OCR rule). Hash, black frame and post-credits detection never convert HDR, so this setting costs nothing there. Frames are scaled down first, but it still adds CPU work and can be slow on weaker systems. Works with the Hardware Acceleration setting above; if your hardware setup cannot run it, the plugin logs a warning and continues without it. Normal video and Dolby Vision without an HDR10 base are never converted.

expand_more Post-Credits Scenes

Some episodes return to the story after the credits. Skipping the credits would jump straight past that scene. When enabled, the plugin checks the part of each episode after the detected credits for picture content that returns after a dark credits section. It measures how much of the frame is black, which works the same for normal video, HDR and Dolby Vision, so no tone mapping is needed. Hardware decoding follows the Hardware Acceleration setting under Performance & Resource Control.

Default: Off. Adds a short extra FFmpeg pass per detected episode. Credits that roll over the show's picture can't be told apart from a scene, so those episodes are never flagged.
Default: Flag. Flag keeps the normal credits marker and adds a warning to the detection results and log. Move places the credits marker after the scene so skipping keeps the scene. If the scene runs to the end of the video, no credits marker is saved (an older one is removed) so nothing gets skipped, and a normal chapter named "Post Credits" is added where the scene begins so viewers can jump to it from the chapter list. That chapter is updated or removed when the episode is detected again.
Default: 10. Picture content after the credits must last at least this long to count as a scene. Raise it if short studio logos are being flagged.
